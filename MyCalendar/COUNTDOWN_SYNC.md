# 日程与倒计时联动

MyCalendar 是日程的唯一保存位置。Home Widgets 订阅已保存的日程，将其与独立创建的倒计时合并展示；不会再次保存日程标题或日期。

## 使用方式

1. 同时启用支持联动的 MyCalendar 和 Home Widgets。日程弹窗只有在联动能力已连接时才显示「同步到倒计时」开关。
2. 新建或编辑日程时勾选「同步到倒计时」。新建日程默认关闭，已有日程也可以开启。
3. 日期显示在 Home Widgets 唯一的倒计时列表，不需要选择集合。

倒计时使用日程标题与**开始日期**，按自然日计算；跨天日程规则相同，不包含时分、备注、颜色或结束日期。修改日程后自动更新，展示身份保持不变。关闭关联或删除日程后，关联倒计时会移除，独立倒计时不受影响。

关联条目标有「日历同步」。标题与日期在 MyCalendar 修改；Home Widgets 可以置顶、归档和恢复。归档状态由 Home Widgets 保存，置顶按组件实例保存。同首页多窗口共享唯一倒计时实例及其置顶配置。

## 停用与失败处理

- Home Widgets 未启用或不支持当前接口时，隐藏关联选项。已打开的日程弹窗也会立即响应能力变化，重新连接后恢复显示；不要求页面已经添加倒计时组件。
- 隐藏选项时保留已有设置和本次未保存的关联草稿，随日程保存、重新连接后生效，并显示只读提示。标题、日期、备注等编辑内容不会因连接变化而重建或清空。单独使用 MyCalendar 的新日程不显示联动入口或提示。
- MyCalendar 停用时显示「日程来源未连接」，保留本次运行已读取的展示内容与本地归档、置顶状态。重新启用后重新订阅。
- 日程标题、日期等缓存只在内存中；重启后来源仍未连接时，不会从 Home Widgets 恢复这些业务字段，但展示状态继续保留。
- 保存日程成功后才发出变化通知。日程保存失败保留弹窗及原数据，不发布未保存的修改。
- 读取失败或接口不支持时显示明确状态，保留上次有效结果；不会把读取失败当成空列表。
- 展示状态保存失败时保留原本地状态并提示、重试。有效快照已确认删除的日程仍立即从展示中移除，不依赖本地状态清理成功。
- 集中检测每秒检查一次来源是否出现或更换；连接后通过变化通知读取快照，连续通知合并处理。表单编辑期间延迟刷新，关闭表单后应用最新结果。

## 只读数据源接口

`MyCalendar.countdownSource` 使用独立的 `version: 2`，不依赖 Home Widgets 组件注册 API 的版本。契约位于 `shared/calendar-source.d.ts`。

| 方法 | 行为 |
| --- | --- |
| `getSnapshot()` | 返回 `{ revision, events }`；每条日程仅有 `id`、`title`、`date`，来自最后一次成功保存 |
| `subscribe(listener)` | 保存成功且相关日程变化后通知，返回注销函数 |
| `registerDisplayCapability()` | 注册当前可用的展示能力，返回注销函数，用于控制日程弹窗中的关联选项 |

Home Widgets 的适配器负责发现来源、订阅、能力注册、日历组件注册和清理。来源停用或实例更换时注销旧连接；日历为全库单实例，多个视图的样式生命周期独立计数。

派生身份使用 `event-my-calendar-<日程 ID>`。Home Widgets 仅在 `countdowns.calendarDisplay` 中保存归档状态，以及一次性整理后沿用的展示 ID。不存在跨插件写入接口、同步队列或定时推送。

## 当前格式与一次性整理

独立日期使用 `countdowns: { version: 2, events: [...] }`，日程关联使用 `countdown: true`，来源快照 version 2 不接受 collection 字段。组件注册 API 为 v3，MyCalendar 声明单实例。

当前知识库的数据在备份、盘点和确认后一次性整理；日期 ID、内容、归档与置顶保留。正式运行时只支持当前格式，不添加集合别名、复制记录迁移或接口降级。
