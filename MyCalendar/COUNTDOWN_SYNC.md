# 日程与倒计时联动

MyCalendar 是日程的唯一保存位置。Home Widgets 订阅已保存的日程，将其与独立创建的倒计时合并展示；不会再次保存日程标题、日期或目标集合。

## 使用方式

1. 同时启用支持联动的 MyCalendar 和 Home Widgets。日程弹窗只有在联动能力已连接时才显示「同步到倒计时」及集合设置。
2. 新建或编辑日程时勾选「同步到倒计时」。新建日程默认关闭，已有日程也可以开启。
3. 填写倒计时组件使用的「日期集合」，默认 `default`。同一集合可以由多个组件展示。

倒计时使用日程标题与**开始日期**，按自然日计算；跨天日程规则相同，不包含时分、备注、颜色或结束日期。修改日程后自动更新；移动集合保持同一条目的身份。关闭关联或删除日程后，关联倒计时会移除，独立倒计时不受影响。

关联条目标有「日历同步」。标题与日期在 MyCalendar 修改；Home Widgets 可以置顶、归档和恢复。归档状态由 Home Widgets 保存，置顶按组件实例保存。日程移动集合时归档状态保留，旧集合的无效置顶按现有规则清除。

## 停用与失败处理

- Home Widgets 未启用或不支持当前接口时，隐藏关联选项，保留已有日程的关联设置。重新连接后自动读取最新日程。
- MyCalendar 停用时显示「日程来源未连接」，保留本次运行已读取的展示内容与本地归档、置顶状态。重新启用后重新订阅。
- 日程标题、日期等缓存只在内存中；重启后来源仍未连接时，不会从 Home Widgets 恢复这些业务字段，但展示状态继续保留。
- 保存日程成功后才发出变化通知。日程保存失败保留弹窗及原数据，不发布未保存的修改。
- 读取失败或接口不支持时显示明确状态，保留上次有效结果；不会把读取失败当成空列表。
- 展示状态保存失败时保留原本地状态并提示、重试。有效快照已确认删除的日程仍立即从展示中移除，不依赖本地状态清理成功。首次转换复制记录时则必须先保存成功，才能切换展示身份与归档状态。
- 集中检测每秒检查一次来源是否出现或更换；连接后通过变化通知读取快照，连续通知合并处理。表单编辑期间延迟刷新，关闭表单后应用最新结果。

## 只读数据源接口

`MyCalendar.countdownSource` 使用独立的 `version: 1`，不依赖 Home Widgets 组件注册 API 的版本。契约位于 `shared/calendar-source.d.ts`。

| 方法 | 行为 |
| --- | --- |
| `getSnapshot()` | 返回 `{ revision, events }`；每条日程仅有 `id`、`title`、`date`、`collection`，来自最后一次成功保存 |
| `subscribe(listener)` | 保存成功且相关日程变化后通知，返回注销函数 |
| `registerDisplayCapability()` | 注册当前可用的展示能力，返回注销函数，用于控制日程弹窗中的关联选项 |

Home Widgets 的适配器负责发现来源、订阅、能力注册、日历组件注册和清理。来源停用或实例更换时注销旧连接；组件共享样式按文档引用计数，移除一个实例不会影响其他实例。

派生身份使用 `event-my-calendar-<日程 ID>`。Home Widgets 仅在 `countdowns.calendarDisplay` 中保存归档状态，以及当前开发分支转换时需要沿用的展示 ID。不存在跨插件写入接口、同步队列或定时推送。

## 当前开发分支的数据转换

只处理本分支已经产生的带 `calendarEventId` 的已知复制记录。成功读取新接口快照后，在同一次持久化中提取归档状态、保留展示 ID，并清除复制的业务字段。独立倒计时保持原样；组件已有的置顶可以继续使用保留的展示 ID。

读取或保存失败时保留原数据，之后重试；重复转换不会新增条目。重复关联或不支持的格式明确报错并停止转换，不猜测未知旧格式。
