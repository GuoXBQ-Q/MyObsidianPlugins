# Home Widgets 组件单实例与集成精简方案

日期：2026-10-25
状态：已实施、验证并部署；一次性数据整理已完成。需重启 Obsidian 加载新版。盘点与备份位置见「单实例实施盘点.md」。

## 1. 已确认的目标

- 首页只维护一份布局。
- 单实例约束作用于整个知识库，而不是每个页面、窗口或布局分别限制。
- 内置组件只有“分类待办”允许创建多个实例，其余保留的内置组件均为单实例。
- 外部组件由提供方声明是否支持多实例；MyCalendar 日历声明为单实例。
- 倒计时只维护一份日期列表，用户不再选择 default 或其他日期集合。
- 移除 Dataview 查询、Tasks 查询和 Markdown / 笔记嵌入三个独立组件。第三方插件作为必要的底层支持接入。

本方案记录实施目标与边界；本次代码、数据整理和部署已完成。实际盘点、备份和验证结果见「单实例实施盘点.md」。

## 3. 全库单实例与唯一首页布局

### 3.1 身份与显示

实例数量以持久化的组件实例为准，不按 DOM 节点数量计算。同一首页在多个窗口或标签中打开，是同一个实例的多个视图，应共享配置与数据，分别管理视图生命周期。

- 隐藏实例仍占用该类型的名额，添加入口应提供恢复显示或定位现有实例。
- 外部插件停用时保留实例及配置，重新启用后恢复原实例。
- 删除实例并成功保存后，才能重新创建该类型。
- 未提交的布局草稿不能绕过单实例校验。
- 重新注册组件类型不等于创建组件实例。

### 3.2 推荐实现边界

以知识库内唯一的首页布局作为实例配置的权威来源，首页、插件设置页和所有窗口都通过同一布局存储修改实例。

- 统一首页代码块与设置页使用的布局入口。
- 不再允许通过指定另一个布局路径创建第二套独立首页实例；遇到不支持的布局入口应明确提示，不静默创建新布局。
- 不为已经确认不需要的多布局场景另建一套全库实例索引。
- 实施前检查现有非首页布局的实际用途，尤其是灵感索引等辅助页面。若其当前依赖独立布局，需要明确改为打开或引用唯一首页中的对应组件，避免形成第二个实例。具体导航方式在盘点后确定。

若多个进程同时编辑同一知识库，不能仅依赖内存注册表保证唯一性；最终写入必须针对最新持久化布局校验。跨设备同步冲突不得通过自动删除重复实例解决，应保留数据并明确报错。

## 4. 统一实例数量声明

建议在组件定义中新增：

```ts
supportsMultipleInstances?: boolean;
```

规则：

- 缺省为 false，即全库单实例。
- 分类待办明确声明 true。
- MyCalendar 明确声明 false。
- 其他外部组件可以按自身业务需要声明 true。
- 这是开发者声明的组件能力，不是用户可切换的实例设置。
- 注册时检查字段类型，并同步更新公开类型声明、文档和示例。

限制必须同时覆盖：

1. 添加界面：已存在的单实例组件显示“已添加”，提供定位或恢复入口。
2. 创建接口：在读取最新布局后校验，不仅依赖按钮禁用。
3. 布局保存：处理连续点击、多窗口并发和草稿提交冲突。
4. 布局加载：对重复实例明确报告，不自动保留第一项并丢弃其他配置。

外部组件未连接时，已有实例继续保留；该类型未注册期间不能新增。重新连接时依据当前组件声明验证已有实例。

同步修复注册清理的归属问题：旧注册返回的注销函数只能清理该次注册，重复执行不得删除后来注册的同类型组件。

## 5. 倒计时取消多集合

### 5.1 用户界面

- 删除倒计时设置中的“日期集合”。
- MyCalendar 日程保留“同步到倒计时”开关，删除目标集合选择。
- 添加或编辑独立日期时不再选择集合。
- 保留置顶、取消置顶、归档、恢复、过期日期展示与列表展开功能。

### 5.2 数据与接口

- 独立日期统一保存在 Home Widgets 的一份日期列表中。
- 日历来源接口不再要求 collection 字段。
- 日期服务的读取、保存、删除和归档接口取消集合参数。
- 集合事件通知改为针对唯一日期列表的通知，取消集合路由。
- 组件显示独立日期与已开启同步的 MyCalendar 日程。
- MyCalendar 继续是日程业务数据的唯一保存位置，Home Widgets 不复制保存日程标题和日期。
- Home Widgets 保留日程展示身份与归档状态，置顶保存在唯一倒计时实例的配置中。
- 继续区分来源断开、读取失败与有效空列表，避免错误清理置顶或归档状态。

具体存储格式和接口版本在实现时统一确定。若契约发生破坏性变化，应明确调整版本并同步双方，不增加旧字段别名或降级分支。

## 6. 移除独立组件，保留必要支持

| 项目 | 处理方式 |
| --- | --- |
| Dataview 查询组件 | 移除注册、组件实现、专属样式及专属测试 |
| Tasks 查询组件 | 移除注册、组件实现、专属样式及专属测试 |
| Markdown / 笔记嵌入组件 | 移除注册、组件实现、专属样式及专属测试 |
| Tasks 任务转换能力 | 保留分类待办需要的调用与保护逻辑 |
| QuickAdd | 保留速记及命令组件需要的集成 |
| Markdown 渲染能力 | 检查保留组件和公开契约的实际用途后决定，不随组件机械删除 |
| Dataview 适配与状态入口 | 若删除查询组件后无实际调用方，则一并移除 |

这不涉及卸载用户安装的 Dataview、Tasks 或其他插件，也不删除它们自己的配置和笔记内容。

公共能力若原本属于外部组件契约，需要评估契约变更，不能仅凭内置组件不再调用就直接删除。

## 7. 当前数据的一次性整理

实施前先输出只读盘点清单，包括首页及辅助布局路径、组件实例、日期集合和配置差异。

### 7.1 重复实例

- 列出各单实例类型的全部现有实例及其配置。
- 无冲突时整理为唯一实例；有内容或来源差异时，由用户确定保留或合并方式。
- 不以“第一个实例”为默认依据静默丢弃其他实例。
- 特别检查 Banner 内容、速记草稿、快捷链接、命令配置和灵感目录。
- 保留实例 ID 时尽量维持相关本机草稿与状态的关联。

### 7.2 日期集合

- 汇总各集合的独立日期，保留日期内容与归档状态。
- 相同标题不能作为自动去重依据。
- 检查日期 ID 冲突，制定明确的处理映射。
- 多个旧倒计时存在不同置顶时，确定最终保留的置顶日期。
- 日历关联记录按日程身份核对，避免将派生日期再次保存成独立日期。

### 7.3 被移除组件的配置

移除布局引用前，保存原 Dataview/Tasks 查询语句、Markdown 嵌入路径和内联文本，避免丢失用户内容。

上述整理是针对当前知识库的一次性操作：先备份，准备可检查的变更清单，确认有冲突的取舍后执行。它不意味着为插件新增长期旧版本迁移或兼容逻辑。正式运行时只维护当前格式，对不支持的格式明确报错。

## 8. 实施顺序

1. 盘点首页、辅助布局、重复实例、日期集合及被移除组件的现有配置。
2. 确定唯一首页布局入口，以及重复配置的保留和合并清单。
3. 增加组件多实例能力声明，完善创建与保存约束，修复注册清理归属。
4. 将 MyCalendar 接入统一实例规则，并简化双方的日期同步契约。
5. 简化倒计时存储、服务、事件通知与界面。
6. 移除三个独立组件及确认无用途的专属代码，保留必要集成能力。
7. 按确认清单整理当前数据，更新文档和有意义的行为测试。
8. 验证后再按实际授权进行部署或提交，不把本方案文档视为部署授权。

## 9. 验收重点

- 每种单实例组件在整个知识库只能持久化一个实例。
- 分类待办以及明确声明支持多实例的外部组件仍可创建多个。
- 隐藏、插件断开和重连不会释放或重复占用实例名额。
- 同首页多窗口打开能共享配置，不把视图挂载误判为重复创建。
- 连续添加、并发添加、草稿提交与放弃不会绕过数量限制或丢失配置。
- 不再存在可创建独立实例的第二套布局入口；辅助页面按确认的方式接入。
- 倒计时和日历界面不再要求选择集合，日期内容、归档和选定置顶完整保留。
- 来源断开、读取失败、保存失败和重试仍保持现有数据保护。
- Dataview、Tasks、Markdown 嵌入不再出现在独立组件列表中。
- 分类待办所需 Tasks 支持、速记所需 QuickAdd 支持正常。
- 旧注销函数重复调用不会删除新的同类型注册。

按实际影响运行组件、布局、持久化和跨插件集成测试。界面验证覆盖添加、恢复隐藏、日历同步选项及必要窄屏表现；模拟环境通过不等同于真实 Obsidian 验收。

## 10. 本次不扩大的范围

- 不将所有文件、目录和查询来源强制改为统一集合存储。
- 不删除保留组件仍需要的数据来源配置。
- 不为本次精简另外建设大型组件 SDK 或通用数据平台。
- 不借本次修改重做与单实例及组件移除无关的界面。
