## 1. 层级与范围（Q1、Q9）

- 最多两层：**主待办 → 子待办**。子待办不能再添加子待办。
- 普通主待办可以独立存在，也可以拥有多个子待办。
- 子待办继承父项分类，可以有自己的截止日期。
- 本次仅支持普通父子待办。重复待办继续独立使用，不能加入父子组，也不能添加子待办。
- 来源笔记中已有包含重复任务的父子组时，明确提示并阻止整组联动，避免错误生成下一轮任务。
- 图片看起来有更深的层级，用户明确选择只做上述两层；图片中的“4 秒撤销”也未选入本次范围。

## 2. 创建与编辑（Q7）

- 父项旁提供“＋子待办”入口；点击后展开该组，在组内就地输入，首次自动聚焦。
- 按用户后续修订：Enter 或“添加”保存一条后关闭行内输入区，不自动开启下一条；用户再次点击“＋子待办”才添加下一条。Esc 退出行内添加。
- 子项截止日期独立可选；输入和编辑需沿用现有日期组件及主题风格。
- 2026-10-22 最新界面修订：上方整行输入子待办内容，下方左侧为紧凑日期框，日历图标内嵌于日期框右侧，下方“添加／取消”按钮靠右对齐；主项与子项的勾选框按首行文字行高居中对齐，多行文本也以首行为准。
- 给已完成父项添加新的未完成子项，会将父项恢复为未完成；已有子项的勾选状态保持不变。
- 主待办现有添加和编辑能力应继续可用。子项也可以编辑标题、日期。
- 中文输入法选字期间不得将 Enter 识别为提交；保存失败应保留输入，避免丢失草稿。这是实施质量要求。

## 3. 完成状态联动（Q2、Q4）

| 操作 | 父项结果 | 子项结果 |
| --- | --- | --- |
| 勾选未完成父项 | 完成 | 全部完成 |
| 取消勾选已完成父项 | 未完成 | 全部未完成，包括原先已完成的子项 |
| 勾选一个子项，仍有未完成子项 | 未完成 | 完成该子项，并带所属说明移到组末尾 |
| 勾选最后一个未完成子项 | 自动完成 | 全部已完成，本次子项移到组末尾 |
| 取消勾选任意已完成子项 | 自动恢复未完成 | 只恢复该子项，其他子项保持状态 |
| 给已完成父项添加子项 | 自动恢复未完成 | 新子项未完成，已有子项不变 |

- 无子项的主待办保持普通独立待办行为。
- 有子项的父项显示“已完成子项数／全部子项数”，如 `1/3`。被隐藏的子项仍参加进度计算。
- 父项完成或恢复后，整组移动到对应顶层完成分区的末尾；子项内部顺序不变。
- 整组完成、取消完成必须一次性保存，失败不能留下只改了一部分的组。

## 4. 折叠、隐藏与恢复（Q5、Q6、Q10）

三个动作必须区分：

| 动作 | 是否修改完成状态 | 显示效果 |
| --- | --- | --- |
| 取消完成 | 是，按上节联动 | 回到未完成状态 |
| 折叠父项 | 否 | 保留父项，收起子项 |
| 隐藏已完成项 | 否 | 在当前组件中隐藏子项或整组 |

- 父项默认展开。折叠状态按组件实例记住，不影响同一来源的其他组件。
- **完成后不自动隐藏**，由用户手动隐藏。
- 已完成子项可以单独隐藏；已完成父项可以整组隐藏。
- 隐藏不删除任务、不改变完成状态、不影响统计和父项进度。
- 标题栏“还原隐藏待办”恢复当前组件全部隐藏项的显示，保持其完成状态，并开启“显示已完成”。
- 关闭“显示已完成”：已完成父项连同子项不显示；未完成父项下的已完成子项不显示。父子归属不得被打散。
- 取消完成会清除此项的隐藏记录，避免它下次完成时再次自动消失。整组取消完成要处理整组；单独恢复子项时也要处理随之恢复的父项。
- 隐藏徽标按操作对象计数：隐藏整组记 1，单独隐藏子项各记 1；被整组隐藏覆盖的子项不能再次重复计数。
- 隐藏、折叠只在当前实例生效；任务的完成状态是共享笔记内容，会同步到其他读取该来源的组件。

## 5. 拖拽与顺序（Q3、Q6、Q10）

- 仅同级排序。顶层父项只能在同一分类、同一完成分区内排序；子项只能在同一父项下排序。
- 不支持跨父项移动子项，不支持拖入变子项或拖出变主待办。
- 拖动父项时，其全部子项和缩进说明作为整块一起移动，包括当前折叠或隐藏的内容。
- 保留顶层“未完成／已完成”分区，各分区内使用手动顺序。
- 按后续修订：单独完成子项时移到原父项的组末尾，其余子项保持相对顺序；取消完成保留当前位置。父项一键完成整组时保留子项顺序。仍可手动拖拽调整同级顺序。
- 截止日期只作提示，不能覆盖手动排序。
- **排序写回 Markdown 笔记**，读取同一来源的组件同步顺序；重启后仍有效。
- 使用专用拖拽手柄，显示落点提示，支持 Esc 取消和键盘排序。
- 拖拽期间取消、失去焦点、卸载等场景要清理临时状态；保存失败或检测到并发修改时不覆盖新内容。
- 显示上限按顶层主待办组数计算，不在组内部截断子项。

## 6. 删除（Q10）

- 删除父项须确认；确认后删除父项及其全部子项和所属缩进说明。
- 删除子项后重新计算父项完成状态。若剩余子项全部完成，父项随之完成。
- 最后一个子项被删除后，父项变回独立待办，保留删除前父项当时的完成状态。
- 删除必须检测任务及子块是否已被外部修改，避免误删。

## 7. 统一统计口径（Q8）

- 只统计最末级待办：有子项的父项不重复计数；无子项的独立主待办算 1 件。
- “父项＋3 个子项”算 3 件；父项的 `1/3` 表示子项完成情况。
- 分类待办卡片总进度、今日概览、完成热力图使用同一口径。
- 隐藏、折叠、显示上限都不影响实际任务数量和完成数量。
- 完成热力图仍使用最末级已完成任务的有效完成日期；无有效完成日期不推测。

3. 外部笔记含更深层级或显式异类子项时，不能静默截断、扁平化、误改或误删。仓库要求不支持的格式明确报错；提示应让用户能到笔记修正。

7. 同一来源在不同组件中刷新时，不得把子项显示成孤立的主项，也不得因为 limit 切断父子组。
8. 新增稳定 ID 的操作可能引发重挂载，需保证后续隐藏、折叠、连续输入操作使用最新身份而非失效快照。
