# 验证范围

- 修改界面前阅读并遵守 [开发注意事项](开发注意事项.md)，尤其是悬停提示去重和下拉框统一使用自定义样式的约定。

- 只维护当前格式与接口，不添加旧版本迁移、字段别名、接口降级或未知结构字段透传。格式或字段不受支持时明确报错。普通可选配置默认值、插件未启用提示和数据写入保护属于当前功能，应保留。

- 按改动影响选择验证。文案、颜色、间距等低风险调整不新增自动测试；界面调整只检查受影响的界面和必要的窄屏表现。
- 单个组件或服务的逻辑修改只运行对应测试文件。修改公共布局、持久化、生命周期、适配器或构建入口时，再根据影响扩大到相关测试或 `npm test`。
- 直接运行 `node --test tests/<name>.test.cjs` 可做定向验证；`plugin.test.cjs` 使用构建产物，运行前需要 `npm run build`。
- 浏览器脚本按涉及的交互或样式选择运行，不作为每次修改的必跑步骤；无需重复检查无关组件、固定次数地重开页面或反复截图。
- 保留能发现数据丢失、误删、并发覆盖、保存失败和生命周期问题的行为测试。不添加只匹配源码文字、固定内部结构或重复现有断言的测试。
- 检查通过后结束验证。只有新改动、失败或尚未解决的问题才需要重跑；说明实际执行的检查，不把模拟环境当作真实 Obsidian 验收。
